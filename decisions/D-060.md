# D-060 Properties and rights

Topics: [[actions]], [[window]]

(the owner, through the Proceed on block FM) Properties (F9) works on both sides and on several files: name, kind, size, date, link target, owner, group and rights, and a field where the files differ says so. Rights are a grid of boxes with set user, set group and sticky, kept in step with an octal field and a Copy button; a box where the files differ starts as "leave as it is", so only the boxes the person touches change. Only the boxes the person touched change, for one file as for several and for everything inside; every other box stays as each file has it. On the server the change is one command line with exactly the touched boxes (as `u+rw,u-x,…`), shown and confirmed first (OR-5, OR-6); for everything inside it goes through `find`, files first and folders deepest first, so nothing is changed before it was read, and never with `X`, which also gave Run to files. "Give folders Run where they get Read" is off at first; when on, the folders inside get Run only for the classes whose Read box the person switched on in this change; "inside" alone changes nothing. This computer gives the same result. Without a shell, rights go through the protocol file by file, a refusal never stops the rest and is reported, and everything inside is not offered. Owner and group are drop-downs from the server's own lists with a shell, otherwise from the names seen in listings; the lists only suggest: any name without a hyphen first, a colon or a control character is accepted, also of a directory, is always quoted, and an unknown one is refused by the server or this computer in its own words. Without a shell and with rights the server did not tell, the window says before OK that rights can only be set as a whole, and OK waits for every box or a full octal number. The New Folder window can set rights. OK is usable only when something changed. Why: the reference program works this way, and a box the person did not touch must never change a file.
