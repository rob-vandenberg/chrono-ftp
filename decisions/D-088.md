# D-088 Checksums without a shell

Topics: [[actions]], [[connections]]

(through the Proceed on block FE, 2026-11-13) One checksum function picks the best way the connection offers, detected and never assumed ([[D-016]]): with a shell the server's `md5sum` to `sha512sum`, one command line for many files, each file read through standard input so no name ever comes back; without a shell SFTP's `check-file`, where the server names it in its hello, or FTP's `HASH` (chosen with `OPTS HASH`) and the older `XSHA256`, `XMD5` and the like, where FEAT names them; otherwise greyed with the reason. A checksum through the protocol runs on a channel of its own (SFTP, over the same login) or a login of its own (FTP), so the tab never waits for it; a stop ends the file that runs at once; where the FTP server takes no further login, the window says calmly that the tab waits. Every answer is checked as input, and an answer for another algorithm is refused. A file on this computer is read in pieces. The second step of compare ([[D-020]]), Compare Contents in Synchronize, uses this function, so it works without a shell where the server computes checksums ([[D-027]]). Why: the reference program computes checksums over SFTP, FTP and the shell alike, and the server's own work keeps the file off the line.
