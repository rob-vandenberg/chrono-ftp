# D-099 Copy and paste files between tabs

Topics: [[window]], [[transfers]]

(through the Proceed on block FI, 2026-11-13) Ctrl+C on the list with the focus notes the files chosen and puts their full paths on the clipboard, so another program gets them too; Ctrl+V in another tab brings them there (OR-21: a text field keeps its own Ctrl+C and Ctrl+V). From this computer to a server it is an upload, from a server to this computer a download, both through the transfer window and the queue, so the overwrite question and the stop are the ones a person already knows. Between two tabs on the same server the server makes the copy itself where it can, exactly as Copy To does, and a name that is taken is never written over; where it can't, and between two different servers, each item is fetched to this computer first and sent on once it has arrived, as two items in the queue that can be watched and stopped. Where nothing of ours is on the clipboard, a single path on it opens that folder on the side it was pressed on. A paste into a folder, on this computer or within one server, is done by Chrono FTP in one and the same window, which says what will happen and has the one button that reads Start and then Abort ([[D-097]]): while it runs it says "Copying 3 of 12: <name>", naming what it is busy with from the moment it starts; Abort and closing the window both end it after that one item, and it says afterwards what was done and names every item that could not be, with its reason. Something that is already there is asked about first, with the same question a transfer asks, worded for a copy (nothing is sent, so Append and Resume are greyed with that reason). A copy that replaces something is made under a name of Chrono FTP's own and takes the place of the old one only once it is whole: the old one is moved aside, the copy takes the name, and only then is the old one removed, so a copy that breaks off never costs the person what they had, on this computer or on a server (G-2). Where the old one could not be removed afterwards, the window says it stays under its aside name. a thing pasted into the folder it is already in becomes "note (copy).txt" beside it on both sides, and the window says so before Start. A file is never written into a folder of its name and a folder never over a file of its name: both are refused with their reason, as is a folder pasted into itself (G-2, OR-20). The copying itself is the one of `transfers/sidework.py`, and the Start/Abort button and the words of a run on this computer live in `ui/startabort.py`, shared with the Synchronize window. Every refusal is a greyed menu entry with its reason, and Ctrl+V on a greyed entry says that reason in the status bar: nothing of ours is on the clipboard and no path that side could go to, or the tab the files came from is closed or not connected. Why: the reference program's copy and paste between sessions, and the person needs no drag across a window full of tabs.
