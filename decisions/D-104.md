# D-104 The installers

Topics: [[way-of-working]], [[program]]

(through the Proceed on the packaging folder, 2026-11-14) Chrono FTP is handed out as one `.deb` and one `.rpm`, each carrying its own Python 3.14, Qt and the program in `/opt/chrono-ftp`, so the person installs one file and nothing else ([[D-025]], OR-29). They are built by `packaging/`: Nuitka compiles the program inside an Ubuntu 22.04 container, because a program built on an older system also runs on newer ones and not the other way round, and nFPM packs that folder. Everything the build needs from outside is fetched once into a builder image and a wheel cache, so a build downloads nothing. The packages name `rsync` and the SSH client (`openssh-client` on Debian and Ubuntu, `openssh-clients` on Fedora and openSUSE) as dependencies and let the person's own package manager install what is missing, where the person sees it happen; no script inside a package ever runs a package manager itself, which would break an offline install and act as root on something the person never saw. The terminal program and `xdg-open` stay out of the dependencies: naming one terminal would drag a foreign desktop's terminal onto the machine, and both are detected at run time with what is missing greyed out ([[D-016]], OR-7). The packaged program has no `pyproject.toml` beside it, so its own package information and its licence file go into the program folder, or the About window would have no version, no repository address and no licence ([[D-059]]). App information (AppStream) goes in too and names its package, or software centres do not list Chrono FTP as installed and it cannot be removed there. Each package is started in a bare container as a normal user before anything is released, because a test on the machine that built it can pass for the wrong reason. Nothing reaches the GitHub release page unless `./build-release.sh --upload` is given, and only the owner gives it, for a version the owner installed and tried (OR-29, OR-30). Why: a person who wants to use Chrono FTP should not have to know what Python is.
