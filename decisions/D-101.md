# D-101 Folders in the connection list

Topics: [[window]]

(through the Proceed on block FJ, 2026-11-14) A connection stands in a folder of the list when its name holds a slash: "Work/Mail server" stands in the folder Work, and folders hold folders. The folder is part of the name, so the saved file keeps exactly what it kept before ([[D-017]]), and the list shows it as a tree, with the connection's own name under its folder. Dragging a connection onto a folder, or out of every folder, is that same rename, done by the one rename path of the connections window, so its password, its bookmarks, its location profiles, its place in every workspace, its place in the tab row and the connection the window starts on all come along (FJ-02). The password goes first, as a copy; then the list is written; and only once that has succeeded is the old password removed, so no step in between can leave a connection without its password. Before any of that, every file that has to follow the new name is asked whether it can be written — the connection list, the settings, the workspaces and the bookmarks — by writing as many bytes as that file holds and flushing them to the disk, so a disk with no room left says so before anything is renamed. Then the stores that follow the name are written first and the connection list last of all, and a store that can't be written puts back exactly what stood there before, so a move that can't be made whole changes nothing and drags no left-over along. What the person then reads is built from the facts there are, in one short sentence: "Nothing changed: Mail is as it was.", followed by what could not be saved; a connection that is new says "Work was not saved." instead, because there is nothing it could be as it was. Where something is left under the other name it reads "Mail is as it was, but the name Work/Mail now holds its bookmarks.", and then every file that could not be saved, why it stopped first. A password store says which call failed, never why; a copy of a password left behind is said after what happened, never before it. There are no paired texts for a drag and a typed name, no advice that can be wrong, and nothing in a sentence that can come out untrue when a name is empty or the same on both sides (the owner, review round 6). A deleted connection leaves nothing behind — not the connection the window starts on, not a place in the row of tabs, not the settings a new connection starts from, in the window nor in the file — and a rename never puts a name twice in the order of the tabs. Deleting one and copying one go the same way as every other write: the list is saved first, and where it can't be saved nothing changes and the person is told (OR-15). Where one of them can't, or the password can't be copied, or the list can't be saved, nothing is moved at all and the window says so in plain words, because a connection without its password, or with its bookmarks left behind, is not the connection the person had (OR-24, G-2). No write in that chain is ever swallowed in silence. A name already taken in that folder says exactly that, in its own words, and nothing moves; a connection never lands in a folder of its own name. A name with an empty part ("Work/", "A//B") is refused when it is saved, and the spaces around each part are trimmed, so no row and no folder of the list is ever blank or called " Work ". Which folders stand open is kept with the other settings, so the window looks the way it was left, and a folder a connection just moved into stands open, so the person sees where it went. The right-click menu of a folder holds Open Every Connection in This Folder: a tab for each connection in it and in its folders, in the order the tree shows them, greyed with its reason where the folder holds none (OR-20). Typing letters in the list jumps to the first connection whose own name starts with them, as typing in the file list does ([[D-072]]), with what was typed shown under the list and the folder of a match opened, so the person always sees why the selection moved. Why: the reference program's folders of sites, and a list of thirty connections is unreadable in one flat row.
