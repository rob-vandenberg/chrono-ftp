# D-102 Reading the SSH settings of this computer

Topics: [[window]], [[connections]]

(through the Proceed on block FJ, 2026-11-14) Import offers a second way in beside a session list ([[D-021]]): the SSH settings this computer already has, `~/.ssh/config`. What stands above the first Host line counts for every server, as OpenSSH reads it, and refuses every server where it is a setting Chrono FTP can't follow. Every server named by a Host line without a star or a question mark is offered in a window with a tick, with its name, the server it reaches, its port, its user and its key file; a Host line with a star in it is a rule for the others, as OpenSSH reads it, and the first value of each keyword wins. A name with a slash in it becomes a name with a space, so an imported server is never a folder of the list. Everything after an unquoted # is a comment, as OpenSSH reads it, so a comment never reaches a value and the words of a comment on a Host line are no servers. The file is read once for every server in it, because a person waits for it (G-2). Every value is read as a word of its own, and what a setting writes as a token is worked out: ~, $HOME, ${HOME}, %d, %u and %h, where %h is the server the connection really uses. A value that is not quoted and holds more than one word is no value Chrono FTP can act on, so it refuses its server; what stands in quotes is one value, spaces and all. A network address needs no square brackets here, as this computer's own settings write one. The name of a server is read by the same one place a pasted address uses ([[D-103]]), so one rule says what a server name is. "none" says a setting is not in use, for a key file as well as for the keywords that refuse. What cannot come over yet is named per server in plain words and that server is not ticked and cannot be ticked, because nothing is ever taken over half: a server reached through another one (ProxyJump, ProxyCommand, which is block FK), a login with a signed certificate, a key on a smart card, a setting that still holds something that can't be worked out, a setting far longer than any setting a person writes, a name that is no server name, a value with a character that can't be in it, a value of more than one word that is not quoted, and a port that is no port (a port is a number from 1 to 65535). Every reason is said in the person's own words, without a keyword of the settings file in it, names the cause and the character or the short-hand it found, keeps what it echoes back short, stands once however often the file says it, and says what the person can do. Where Chrono FTP cannot do what the file asks at all — a way in through another server, a certificate file, a key on a smart card — the reason is one short line that says what the file asks and that Chrono FTP can't do it; it sends nobody to a terminal (OR-25) and promises no version, here or anywhere else in the block. A name after Host that is no server name says that it is the name after Host, because the person wrote no server there. A network address written as it stands, scope and all, is a server name here; between square brackets it says to write it without them, because brackets belong in an address. Where a connection by hand would not mend it — a way in through another server, a certificate that signs the key, a key on a smart card — it says what the file asks for, that Chrono FTP can't do it yet, and what they can do today instead. A server whose settings can't be read at all refuses only itself, so one odd line never costs the person every other server of the file (OR-15). Where no server at all can come over, Add says that instead of asking for a tick that can't be given (OR-20). Settings that change in a Match section, or that read another file with Include, cannot be judged, so every server of that file says so and none of them comes over. The host keys of `~/.ssh/known_hosts` count as trusted, so a server used before from a terminal is not asked about again. Both files are only ever read: nothing in the person's own SSH setup is written, changed or copied, whatever happens. A name the list already holds comes over under a name of its own, so the list never loses what it has. Three answers are said apart in their own words: this computer has no SSH settings at all, its settings name no server, and its settings could not be read, which names the file and says what to check. The import of a session list says its own three apart as well: a file that could not be read, a file that holds no connection, and a file whose connections the list already holds. Where the list itself can't be written, nothing is added and the person is told. Why: the owner's servers are already set up for the terminal, and typing them a second time by hand is work and a source of mistakes.
