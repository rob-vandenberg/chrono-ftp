# D-103 Addresses

Topics: [[window]], [[connections]]

(through the Proceed on block FJ, 2026-11-14) An address is `sftp://user@server:port/folder` or the same with `ftp://`, the two kinds of connection there are ([[D-009]]). One place reads a server name: a name of letters, digits, dots, hyphens and underscores, never a hyphen first, no part empty, each part at most 63 characters and the whole at most 253; a name with letters of another language is worked out to the form the network uses, so the person can paste the name they know; or a server number between brackets, whose scope after % is a plain name. Only ASCII digits are a port, a user name with a space, a slash or a control character is refused, and a folder with a control character in it is refused: no part of an address may ever reach a command as an option of its own, and nothing hides behind a percent sign. Every cause says its own thing in plain words, told apart in the one place that reads a server name, so this computer's own SSH settings can say the same causes in their own words ([[D-102]]). A network address that holds colons goes between square brackets wherever a login is built, so a tab opened from such an address can send and fetch files too (`core/addresses.login_text`). An address is read one way and one way only: the folder starts at the first slash, the user name with its password ends at the last @ before that slash, and what follows the colon of the server part is the port. So an @ in a folder is a folder, and `sftp://user:12/ss@server/x` names the server `user` on port 12, which is what it says; a password with a slash in it is written %2F, as a password in an address always is. Nothing about an address is guessed at, and nothing that is a proper address is refused: instead the window says what it has read. In Open an Address… what the program has made of the address stands under the field while the person types — the server, the port, the user name and the folder, each named in plain words, that a password came with it, never what it is, and, where no user name was read while the folder holds an @, that too, because a password with a slash in it written as it stands reads that way — and in that same place the one sentence saying it cannot be read at all, with Open greyed and that sentence as its reason (`core/addresses.understood`). So a person who meant a password with a slash in it reads "Server: user" and "Port: 12" before pressing Open and puts it right themselves, and the address that Copy the Address hands out always reads back as the connection it came from. A port that is a number out of its range, or no number at all, says it is no port. One question answers for every tab whether anything of it may be written on this computer, and every lookup of an open tab by name asks it too, so a tab opened from an address never reaches the password, the tab name, the Edit item, the places, the place in the row of tabs, the session log, the information window or the workspaces of a connection that happens to carry the name it was given. The mark that says a connection is in no list sits on the connection itself, so every copy of such a tab carries it and the connection layer keeps its log apart. One question answers for every tab whether anything of it may be written on this computer (`may_keep` in `ui/session.py`), and every writer asks it: the password, the user name a server accepted, the connection that was last live, the place of a tab in the row, a workspace, a bookmark, a location profile, a path typed in the Open folder window, the name a tab was given, the last folders of a tab and the password changed on the server; a copy of such a tab (Duplicate Tab, a further tab of one connection) may not be kept either. Each action that would write something under a tab's name is greyed with that reason (OR-20): Add Bookmark, Add the Current Folders…, Organize Bookmarks and Organize Location Profiles. Every lookup of an open tab by name skips a tab that may not be kept, so a connection later saved under the name such a tab happens to carry can never take it over. Open an Address… in the connections window takes one the person pastes and opens it as a tab that is saved nowhere: it is in no list, its user name is never written back and a password that came with it is used for that one login and written nowhere, not in a file and not in the credential store (OR-19). Its tab is named after the server, under a name of its own where the saved list or an open tab already holds that name, and an address always opens a tab of its own: it never takes over the tab of another connection, which would log that one out and throw its own login away. An address that cannot be read says in one plain sentence what is wrong with it and changes nothing, and the window stays open with what was typed still in it (OR-15, OR-23). Copy the Address, of a connection in the list and of the file or folder under the cursor on the server, puts the address on the clipboard and shows it at once, whole and ready to copy again, so the person sees what they are about to paste somewhere; a password is never in it, and a starting folder that is no path from the root is left out, so the address means the folder the login starts in, which is the truth. A clicked `sftp://` link in a browser or a file manager does not open Chrono FTP: nothing registers Chrono FTP for such links, and the paste window is the only way in, because end-user tasks are graphical and there is no way of using the program from a terminal ([[D-022]], OR-25; the owner, during the changelist of block FJ). Why: the owner gets addresses from colleagues and pastes them, and an address is the shortest way to say where something is.
