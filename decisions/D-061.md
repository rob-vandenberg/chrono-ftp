# D-061 Links and copies on the server

Topics: [[actions]], [[connections]]

(the owner, through the Proceed on block FM) Link… (Alt+F6) makes a symbolic link, or a hard link where the server can, on both sides; on a selected link it changes where the link leads, in one step where the server can (SFTP posix-rename, or `ln` and `mv -T` in a shell), else by moving the old link aside and back on any failure, so the person's link is never lost. Over SFTP links go through the protocol; over FTP Link… is greyed with its reason. Duplicate… and Copy To… (Shift+F5) copy on the server itself: with a shell `cp -a`, without one the SFTP extension copy-data or FTP's SITE CPFR and CPTO where the server offers them (detected, never assumed, [[D-016]]), files only; otherwise greyed with the reason. Copy To… takes a folder, read as the path bar reads it (~ is the login's home, a relative folder starts at the folder shown), and a simple name pattern where * is each file's own name; one refused item never stops the rest, and one message says what was copied and what was not, and why. A name is taken by anything at that path, a link that leads nowhere too. Nothing travels through this computer, a copy never replaces anything, and a copy that fails halfway is removed again. Why: a copy on the server is fast, and the protocol can do it where no shell exists; this changes [[D-027]], where copy needed a shell.
