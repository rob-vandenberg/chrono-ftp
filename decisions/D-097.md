# D-097 One button that starts, and the same button that aborts

Topics: [[window]]

(the owner, 2026-11-13) Work the person starts is started by a button that reads **Start**, and while that work runs the **same** button reads **Abort**: never a second button, never a stop hidden in the status bar. Abort ends the work after the file it is busy with, what was done stays done, and the window says plainly what was done and what was not. Every long-running thing in a window has such a button on screen, naming the one thing it would stop now (OR-20), and closing the window stops it too, so nothing is ever left running where nobody can see or stop it. Where Start hands the work to the queue instead, the queue is opened and the window says where the work went, so the screen tells the truth at the moment the person acts. Why: "Apply" meant nothing to the owner and slipped through four reviews, because each of them read the changelist instead of the screen (G-2).
